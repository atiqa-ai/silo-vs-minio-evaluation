# DEV-912 — S3 API Compatibility and Edge Cases

**Project:** MinIO vs Silo — S3 Storage Evaluation (DEV-904)  
**Evaluation profile:** Option B — 8 CPU cores, 16 GiB RAM, at least 100 GiB SSD, 5–10 GiB test dataset; three workload repetitions per engine.

## 1. Executive Summary

This report covers compatibility across O01–O08 test groups, including malformed requests, authentication, HTTP status behavior, and XML error structures.

## 2. Evaluation Environment

The comparison design uses a single Ubuntu SSD-backed host, sequential execution of MinIO and Silo, equivalent S3 client configurations, consistent dataset manifests, and the same benchmark-tool release. Image digests, application configuration, workload parameters, and hardware inventory belong in the run record.

| Parameter | Common evaluation design |
|---|---|
| CPU | 8 cores |
| RAM | 16 GiB |
| Storage | At least 100 GiB SSD |
| Dataset | 5–10 GiB; small, medium, and large objects |
| Repetitions | 3 per engine |
| Execution order | MinIO, then Silo |
| Comparison rule | Identical input and test conditions |

## 3. Test Configuration

Use a shared test-case identifier, request method, endpoint, headers, payload, expected S3 semantics, response status, and response body fields.

## 4. MinIO Results

MinIO acts as the reference endpoint for HTTP/S3 behavior under each test case.

## 5. Silo Results

Silo is evaluated with the identical request corpus, emphasizing any difference in status code, error code, XML shape, or resulting object state.

## 6. Feature/Performance Comparison

| Test family | MinIO comparison | Silo comparison |
|---|---|---|
| O01–O02 | Core request semantics | Equivalent requests |
| O03–O04 | Authentication and access errors | Equivalent requests |
| O05–O06 | Listing, multipart and metadata | Equivalent requests |
| O07–O08 | Edge cases and malformed requests | Equivalent requests |

## 7. Technical Findings

A successful HTTP response is insufficient when the resulting object state or returned metadata differs from S3 semantics.

## 8. Issues and Limitations

An exhaustive S3 conformance claim requires comprehensive case coverage; the defined O01–O08 groups are the scope of this project.
