# DEV-906 — Dataset Generation and Object Integrity

**Project:** MinIO vs Silo — S3 Storage Evaluation (DEV-904)  
**Evaluation profile:** Option B — 8 CPU cores, 16 GiB RAM, at least 100 GiB SSD, 5–10 GiB test dataset; three workload repetitions per engine.

## 1. Executive Summary

The dataset assessment compares object coverage, manifest determinism, and byte-for-byte correctness after upload and download. Integrity is assessed independently of throughput.

## 2. Evaluation Environment

The comparison design uses a single Ubuntu SSD-backed host, sequential execution of MinIO and Silo, equivalent S3 client configurations, consistent dataset manifests, and the same benchmark-tool release. Image digests, application configuration, workload parameters, and hardware inventory belong in the run record.

| Parameter | Common evaluation design |
|---|---|
| CPU | 8 cores |
| RAM | 16 GiB |
| Storage | At least 100 GiB SSD |
| Dataset | 5–10 GiB; small, medium, and large objects |
| Repetitions | 3 per engine |
| Execution order | MinIO, then Silo |
| Comparison rule | Identical input and test conditions |

## 3. Test Configuration

Use `scripts/dataset/generate.py`, `plan_profile_b.py`, `seed.py`, and `scripts/verification/manifest.py`, `compare.py`. Record object key, size, content digest, and test bucket.

## 4. MinIO Results

For MinIO, compare the downloaded object digest with the manifest SHA-256 digest. Record mismatched, missing, and duplicate object keys separately.

## 5. Silo Results

For Silo, use the identical object manifest and digest comparison; bucket and object naming should match the MinIO test.

## 6. Feature/Performance Comparison

| Check | MinIO assessment | Silo assessment |
|---|---|---|
| Object count | Manifest count vs returned count | Same manifest count vs returned count |
| Object bytes | Original vs retrieved | Original vs retrieved |
| SHA-256 | Digest equality per object | Digest equality per object |
| Missing keys | Enumerate differences | Enumerate differences |
| Data coverage | Small/medium/large objects | Same size distribution |

## 7. Technical Findings

SHA-256 provides a content-integrity comparison. Identical object names and sizes do not, by themselves, establish content equality.

## 8. Issues and Limitations

Checksum success does not establish object-lock, versioning, or replication parity. These belong to other DEV reports.

## 10. Final Conclusion

A single manifest and a common digest algorithm provide the strongest direct basis for object-integrity comparison.
