# DEV-909 — Replication and Consistency

**Project:** MinIO vs Silo — S3 Storage Evaluation (DEV-904)  
**Evaluation profile:** Option B — 8 CPU cores, 16 GiB RAM, at least 100 GiB SSD, 5–10 GiB test dataset; three workload repetitions per engine.

## 1. Executive Summary

This report compares source-to-destination object synchronization, metadata propagation, version behavior, and recovery after connectivity interruptions.

## 2. Evaluation Environment

The comparison design uses a single Ubuntu SSD-backed host, sequential execution of MinIO and Silo, equivalent S3 client configurations, consistent dataset manifests, and the same benchmark-tool release. Image digests, application configuration, workload parameters, and hardware inventory belong in the run record.

| Parameter | Common evaluation design |
|---|---|
| CPU | 8 cores |
| RAM | 16 GiB |
| Storage | At least 100 GiB SSD |
| Dataset | 5–10 GiB; small, medium, and large objects |
| Repetitions | 3 per engine |
| Execution order | MinIO, then Silo |
| Comparison rule | Identical input and test conditions |

## 3. Test Configuration

Define source/destination buckets, replication rules, versioning state, timestamps, and object manifest. Check object count, content digest, metadata, and deletion/version propagation where supported.

## 4. MinIO Results

MinIO replication assessment includes configuration, propagation delay, version correspondence, and recovery after interruption.

## 5. Silo Results

Silo replication assessment follows the features exposed by its deployment; equivalent bucket synchronization can be compared when available.

## 6. Feature/Performance Comparison

| Dimension | MinIO | Silo |
|---|---|---|
| New object | Arrival at destination | Arrival at destination |
| Object version | Version-aware transfer | Supported version semantics |
| Metadata | Metadata preservation | Metadata preservation |
| Connectivity loss | Backlog and catch-up | Corresponding recovery behavior |
| Consistency | Source/destination digest equality | Same digest rule |

## 7. Technical Findings

Replication lag should be measured from an explicit start event to a verified destination state, with clocks synchronized.

## 8. Issues and Limitations

Feature availability may differ between systems; an absent native replication mechanism is a capability distinction, not necessarily a storage failure.
